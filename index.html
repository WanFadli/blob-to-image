Blob → Image

Turn raw image bytes — or a base64 / hex / data:image/… dump — back into a viewable, downloadable image. Runs entirely in your browser. Nothing is uploaded.

1. Choose a blob

Drop or pick any file. The tool sniffs image formats (PNG, JPEG, GIF, WebP, BMP, TIFF, ICO, HEIC, AVIF, SVG) from magic bytes, decodes base64 / hex / data:image/… dumps automatically, and checks whether the bytes look encrypted.

Or paste the blob content

Hex bytes, base64, or a data:image/…;base64,… URL — whitespace and line breaks are fine.

Step 1: Binary String (First decoding step)
            ?JavaScript's atob() function decodes base64 text into a raw binary string. Each character in this string represents one byte (0-255). Most bytes are unprintable, shown as "."
          

          
In simple terms: We took that text code and "translated" it. Now we have the raw picture data, but in a form that's still kind of text-like. The dots (.) are characters that can't be shown as normal text.

          
Technical details: atob() converts base64 characters (A-Z, a-z, 0-9, +/, =) → each group of 4 chars becomes 3 bytes of real data

          
Quick example: "iVBO" in base64 → becomes the secret bytes that show as "..." here

          

          
⚠️ Note: This is still not ready for the browser. We need one more step to make it usable.

        


        

          
Step 2: Uint8Array (Convert to numbers the browser understands)
            ?Each binary character converted to a number (0-255). This is the format the browser actually works with for processing images.
          

          
In simple terms: Now we convert those text-like bytes into numbers. This is what the browser's image processor actually understands. It's like translating from one language to another.

          
Technical details: Each character from the binary string → converted to its numeric value (0-255). Zero = nothing, 255 = maximum.

Step 3b: Magic Bytes (Identifying the picture type)
            ?The first 4-12 bytes at the start of every image file are a unique signature. They're called "magic bytes" because they magically tell you what format the image is — like a fingerprint.
          

          
In simple terms: Every picture file starts with a unique "secret code" at the very beginning. Just by looking at these first few numbers, we can tell: "Oh! This is a JPEG" or "This is a PNG" or "This is a GIF". It's like a fingerprint that never lies.

          
Why this matters: Someone could rename a JPEG to ".png" and try to trick you. But the magic bytes at the start always tell the truth about what type of picture it really is.

          
Real examples (first few numbers of each type):

          

            

              🖼️ PNG

              Starts with: 89 50 4E 47

              (Numbers: 137, 80, 78, 71)
            

            

              📷 JPEG

              Starts with: FF D8 FF

              (Numbers: 255, 216, 255)
            

            

              🎬 GIF

              Starts with: 47 49 46 38

              (Numbers: 71, 73, 70, 56)
            

          

          

          
✅ Done! We found the fingerprint. The computer now knows exactly what type of picture this is and can display it correctly.

        

      


      
      

        

          
          4. Is this file scrambled or encrypted?
          ?Checks if the file is locked/encrypted OR just looks scrambled because it's compressed. We look for known encryption signatures and measure how random the data looks.
        

        
In simple terms: We check: "Is this file locked with a password?" OR "Is this just normal compressed image data?" Both look scrambled, but they're different things.

        

        

        

          
Entropy0.00 / 8.00

          

        

        

        
Entropy near 8 = random / encrypted / compressed. χ²/N near 1 = uniform byte distribution; higher = structured data.
